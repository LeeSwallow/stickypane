# stickypane 화면 재설계: 열린 노트, 크기, 페이지 뷰, 선택지

- 작성일: 2026-10-01
- 상태: 검토 대기
- 앞선 문서: `2026-10-01-stickypane-design.md` (저장 방식, 파일 형식, 쓰기 규칙은 그대로 유효하다. 이 문서는 그 문서의 6절 "화면과 조작"을 대체하고, 모양 하나와 명령 하나를 더한다.)

## 1. 왜 바꾸는가

첫 구현을 실제 tmux에서 써 보고(Linear 이슈 23개를 칸반과 요약으로 올림) 드러난 문제다.

- **모든 노트가 조금씩 떠 있다.** 구조 설명처럼 하나를 깊게 읽어야 할 때, 칸반·체크리스트·로그가 같은 크기로 함께 떠서 시선을 나눈다.
- **잘리고 접힌다.** 보드에서는 칸당 5장, 노트 6줄까지만 보이고, 열어도 카드 제목이 칸 폭에서 잘린다.
- **크기를 정할 수 없다.** 큰 칸반과 한 줄 메모가 같은 규칙으로 놓인다.
- **만드는 방법이 불친절하다.** `type: board` 같은 머리말을 사람이 알아야 한다.
- **에이전트가 묻고 사용자가 고르는 수단이 없다.**
- **마우스를 못 쓴다.**

## 2. 원칙

앞선 문서의 원칙(가장 쉬운 길이 기본값, 틀려도 괜찮다, 설정 없음, 터미널에 묶이지 않음)에 넷을 더한다.

1. **고른 것만, 잘림 없이.** 화면에는 열어 둔 노트만 나오고, 열린 노트는 내용을 자르지 않는다.
2. **사람은 형식을 몰라도 된다.** 머리말은 에이전트와 도구가 다룬다. 사람은 말로 시키거나 화면에서 고른다.
3. **키와 마우스 둘 다.** 모든 동작은 키로 되고, 자주 쓰는 동작은 마우스로도 된다.
4. **화면의 상태는 파일에 남는다.** 무엇이 열려 있고 무엇을 골랐는지 에이전트가 파일로 읽을 수 있다.

### 에이전트가 하고 싶은 말마다 위젯이 하나 있다

"무엇을 보여 주고 싶을지 모르니 기본은 다 준비해 둔다"가 목표다. 위젯 수는 한정하되, 에이전트가 일하면서 하고 싶은 말의 종류는 빠짐없이 덮는다.

| 에이전트가 하고 싶은 말 | 위젯 | 상태 |
|---|---|---|
| 지금 이걸 하고 있다, 기다리고 있다 | `status` (상태 줄) | 새로 만듦 |
| 어디까지 했다 | `checklist` | 있음 |
| 무엇이 남았다 | `board` | 있음 |
| 무슨 일이 있었다 | `log` | 있음 |
| 이건 이렇게 생겼다 (설명) | `note`의 페이지 뷰 | 고침 |
| 이런 구조다 | `tree` | 새로 만듦 |
| 이것들을 비교하면 | `table` | 새로 만듦 |
| 어느 쪽으로 할까요 | `form` | 구현됨 |
| 이걸 누르면 이게 실행된다 | `actions` (버튼) | 새로 만듦 |
| 이런 흐름이다 (상자와 화살표) | 노트 안의 Mermaid 블록 | 구현됨 |
| 수치가 이렇다 (막대, 추이, 잔디) | `chart` | 구현됨 |
| 토큰을 이만큼 썼다 | `usage` | 새로 만듦 |
| 기억해 둘 것 | `note` (메모지) | 있음 |

모두 같은 방식이다. 파일 하나가 위젯 하나이고, 머리말의 `type`이 종류를 정한다. 새 위젯은 패키지 하나와 등록 한 줄로 추가한다.

## 3. 화면 구조

```
 ▸ Linear 이슈  ▾ 구조 설명  ▾ 릴리스 준비  ▸ 작업 로그 ●  ▸ 메모          ← 제목 줄
╔ 구조 설명 ═══════════════════════════════════════════════════════════╗
║ stickypane 구조                                                      ║   ← 열린 노트 영역
║                                                                      ║
║ cmd/stickypane    명령 진입점                                        ║
║ internal/doc      파일을 머리말과 본문으로 나눔                      ║
║ ...                                                                  ║
╚══════════════════════════════════════════════════════════════════════╝
╭ 릴리스 준비 ─────────────────────╮
│ ▓▓▓▓▓▓░░░░░░░░ 2/6               │
│ ☐ 실제 터미널에서 확인           │
│ ...                              │
╰──────────────────────────────────╯
 ◐ APP-820 수정 중 · 3/5 단계 · 테스트 162개 통과                           ← 상태 줄
 enter 크게  o 닫기  + - 크기  a 추가  ? 도움말                               ← 바닥 줄
```

- **제목 줄**: 모든 노트의 제목이 한 줄(넘치면 여러 줄)에 나온다. `▾`는 열린 노트, `▸`는 닫힌 노트, `●`는 마지막으로 본 뒤 바뀐 노트, `📌`는 고정한 노트다.
- **열린 노트 영역**: 열린 노트만 크기대로 놓인다. 화면보다 길면 세로로 스크롤한다.
- **상태 줄**: 에이전트가 지금 무엇을 하고 있는지 한 줄로 항상 보인다(8절). `status` 노트가 없으면 이 줄은 없다.
- **바닥 줄**: 지금 쓸 수 있는 키, 알림, 입력창.

포커스는 제목 줄의 노트 사이를 움직인다(닫힌 노트 포함). 포커스한 노트가 열려 있으면 그 노트의 테두리가 이중선이 된다.

"모든 노트가 미리보기로 떠 있는 벽" 화면은 없앤다. 전체를 훑는 역할은 제목 줄이 맡는다.

## 4. 열림 상태

머리말의 `open`이 열림 상태다.

| 값 | 뜻 |
|---|---|
| `open: true` | 화면에 열려 있다 |
| `open: false` | 닫혀 있다 |
| 없음 | 닫혀 있다. 단, stickypane이 떠 있는 동안 새로 생긴 노트는 그 실행 동안 열어서 보여 준다 |

- 사용자가 `o`(또는 제목 클릭)로 열고 닫으면 도구가 머리말을 고친다.
- 에이전트는 보여 주고 싶은 노트에 `open: true`를 쓴다. 빠뜨려도 새 노트는 일단 열려서 보인다. 이때 도구는 파일을 고치지 않는다. 에이전트가 방금 쓴 파일을 도구가 곧바로 고치면 에이전트의 다음 편집이 어긋나기 때문이다.
- 에이전트는 노트의 `open` 값을 읽어 사용자가 지금 무엇을 열어 두었는지 안다.

## 5. 크기

머리말의 `size`가 폭이고, `rows`가 높이다. 둘 다 선택이다.

| `size` | 폭 | 기본으로 쓰는 경우 |
|---|---|---|
| `page` | 화면 전체 | board, 본문이 12줄을 넘는 일반 노트 |
| `half` | 화면 절반 (폭 72칸 미만이면 전체) | checklist, log, chart, form, 그 밖의 일반 노트 |
| `card` | 최소 36칸의 메모지 | 본문이 3줄 이하인 일반 노트 |

- `rows`가 없으면 높이는 내용만큼이다. 있으면 그 줄 수로 고정하고 안에서 스크롤한다. log는 기본 `rows: 10`이다.
- 배치는 앞선 구현의 흐름 배치를 그대로 쓰되, 한 줄을 12칸 격자로 보고 `page` 12, `half` 6, `card`는 폭에 들어가는 만큼 차지한다.
- `+`와 `-`로 `card → half → page`를 오간다.
- **상하좌우로 늘리고 줄인다.** `shift+→`·`shift+←`는 폭을, `shift+↓`·`shift+↑`는 높이를 바꾼다. 폭은 화면을 12칸으로 나눈 격자에서 차지하는 칸 수(`cols: 1~12`)로 두 칸씩, 높이는 `rows`로 두 줄씩 바뀐다. `cols`가 있으면 `size`보다 우선한다. 높이를 내용보다 크게 늘리면 `rows`를 지워 "내용만큼"으로 돌아간다.
- 마우스로 오른쪽 가장자리를 끌면 `cols`가, 아래 가장자리를 끌면 `rows`가 바뀐다. 손을 떼는 순간 머리말에 한 번 쓴다.

## 6. 열린 노트는 자르지 않는다

미리보기 상한(칸당 5장, 6줄, 남은 항목 4개)을 없앤다. 열린 노트는 다음처럼 그린다.

- **일반 노트**: 본문 전체를 마크다운으로 그린다.
- **board**: 모든 카드를 보여 주고, 카드 글은 칸 폭에서 줄을 바꾼다. 카드 사이에 빈 줄을 둔다. 칸 폭이 14칸 미만이 되면 칸을 세로로 쌓는다. 선택한 카드의 상세는 카드 바로 아래에 펼친다.
- **checklist**: 모든 줄을 보여 준다. 긴 항목은 줄을 바꾼다.
- **log**: 파일을 있는 그대로 보여 준다. 꾸미지 않고, 잘리지 않게 줄만 바꾼다. `rows`만큼의 끝부분을 보여 주고 따라간다. 머리말에 `file: logs/app.log`처럼 경로를 적으면 노트 본문 대신 그 파일의 끝을 따라간다(빌드 로그, 서버 로그).

열린 노트 안에서의 조작(카드 옮기기, 체크)은 크게 보기로 들어가지 않고 그 자리에서 한다. 포커스한 노트가 키를 받는다.

## 7. 크게 보기와 페이지 뷰

포커스한 노트에서 `enter`(또는 더블클릭)를 누르면 그 노트 하나가 화면 전체를 쓴다. `esc`로 돌아온다. 앞선 구현의 모달을 이것으로 바꾼다.

일반 노트의 크게 보기가 **페이지 뷰**다.

- 본문 폭을 100칸까지로 제한하고 화면이 넓으면 가운데에 둔다. 긴 줄이 읽기 어렵게 늘어지지 않게 하기 위해서다.
- 제목, 표, 코드 블록, 인용, 목록을 Glamour로 꾸며 그린다.
- 기본은 한 장으로 이어서 스크롤한다. `p`를 누르면 `## ` 제목 단위로 한 페이지씩 넘기는 방식으로 바뀌고, 테두리에 `2/4`처럼 위치가 나온다. `←` `→`(또는 `h` `l`)로 넘긴다.

`stickypane <이름>`으로 실행하면 파일 이름에 그 글자가 들어간 노트만 다룬다. 하나뿐이면 처음부터 크게 보기로 뜬다. tmux에서 창을 여러 개 나눠 창마다 다른 노트를 띄우는 용도다.

## 8. 묻는 문서 (`form`) — 구현됨

처음에는 선택지만 있는 `choice`로 설계했으나, 선택지·입력 칸·버튼을 한 문서에 섞는 `form`으로 합쳤다. 에이전트가 묻고 사용자가 화면에서 답하면, 답이 같은 파일에 남아 에이전트가 읽는다.

```markdown
---
type: form
title: 지금 배포할까요?
open: true
---
빌드가 통과했습니다. 어디에 올릴까요?

## 대상
- ( ) staging
  먼저 올려 보고 확인합니다.
- ( ) production

## 같이 할 일
- [ ] 마이그레이션 실행
- [ ] 캐시 비우기

## 메모
> 

[ 배포 ] [ 취소 ]
```

| 줄 | 뜻 |
|---|---|
| `- ( ) 글` | 하나만 고르는 선택지. 고르면 같은 질문의 다른 `(x)`를 지운다 |
| `- [ ] 글` | 여러 개 고르는 선택지 |
| 선택지 아래 들여쓴 줄 | 그 선택지의 설명 |
| `> 글` | 한 줄 입력 칸. 상자로 그리고 `enter`로 입력한다 |
| `[ 이름 ] [ 이름 ]` | 버튼. 버튼 줄이 없는 폼에는 `[ Submit ]`이 자동으로 붙는다(파일에는 쓰지 않는다) |

- 그 밖의 줄은 일반 노트와 같은 마크다운으로 그린다. 코드 블록 안의 줄은 조작 대상으로 읽지 않는다.
- 같은 종류의 선택지가 이어지면 한 질문이다. 질문의 이름은 바로 위 제목, 없으면 바로 위 줄, 그것도 없으면 `question N`이다.
- `j` `k`로 움직이고 `enter`나 `space`로 고르고, 입력하고, 누른다. 폼이 `enter`를 쓰므로 크게 보기는 `z`다.
- 버튼을 누르면 머리말에 `submitted: <버튼 이름>`과 `submitted_at`이 들어간다. 그 뒤에 답을 바꾸면 두 키가 다시 빠진다. 에이전트가 `write`로 폼을 다시 쓰면 역시 빠진다.

에이전트가 답을 받는 방법은 셋이다.

1. 파일을 읽는다. `(x)`, `[x]`, `> 답`, `submitted`가 그대로 보인다.
2. `stickypane answers <이름> [--json]`으로 질문별 답만 받는다.
3. `stickypane wait <이름> [--timeout 5m] [--json]`으로 버튼이 눌릴 때까지 기다렸다가 답을 받는다. 시간이 지나면 종료 코드 3으로 끝난다. MCP에서는 `read_answers`(`wait_seconds` 선택)가 같은 일을 한다.

아직 없는 것: 필수 질문 검사, 여러 줄 입력, 버튼에 `run:`·`ask:` 달기(8-4절과 합칠 예정).

## 8-1. 상태 줄 (`status`)

에이전트가 지금 무엇을 하는지, 사용자를 기다리는지를 화면 아래 한 줄로 항상 보여 준다. 열고 닫는 대상이 아니고, 열린 노트 영역을 차지하지 않는다.

```markdown
---
type: status
state: working
---
APP-820 수정 중 · 3/5 단계 · 테스트 162개 통과
```

- 본문의 첫 줄이 상태 줄에 나온다. 둘째 줄부터는 상태 줄을 눌러(또는 포커스해서 `enter`) 펼치면 보인다.
- `state`가 앞의 표시와 색을 정한다: `working` ◐, `waiting` ⏸ (사용자 입력을 기다림, 눈에 띄는 색), `done` ✓, `error` ✗. 없으면 표시 없이 글만 나온다.
- `status` 노트가 여러 개면 파일 이름순으로 한 줄씩 쌓는다(최대 3줄). 에이전트 여러 개가 각자 상태를 쓸 수 있다.
- 에이전트는 파일 하나를 덮어쓰기만 하면 된다.

## 8-2. 구조 (`tree`)

들여쓴 목록을 접고 펼 수 있는 나무로 그린다. 코드 구조나 단계 구성을 설명할 때 쓴다.

```markdown
---
type: tree
title: stickypane 구조
---
- cmd/stickypane: 명령 진입점
- internal
  - doc: 파일을 머리말과 본문으로 나눔
  - widget: 모양별 그리기와 수정 의도
    - note
    - board
  - store: 폴더 읽기, 감시, 쓰기
```

- 가지는 `├`, `└` 선으로 잇는다. `:` 뒤의 글은 흐리게 설명으로 그린다.
- `j` `k`로 움직이고 `h` `l`(또는 클릭)로 접고 편다. 접힘 상태는 화면에만 있고 파일에 쓰지 않는다.
- 목록이 아닌 줄은 나무 위에 설명으로 그대로 보여 준다.

## 8-3. 비교 (`table`)

마크다운 표를 폭에 맞춰 그린다.

```markdown
---
type: table
title: 저장 방식 비교
---
| 도구 | 저장 | 충돌 처리 |
|---|---|---|
| kanban-md | 태스크마다 파일 | 잠금 |
| tuiboard | 보드마다 파일 | 수정 시각 확인 |
```

- 칸 폭은 내용에 맞추고, 화면보다 넓으면 긴 칸부터 줄을 바꾼다.
- `h` `l`로 열을 고르고 `s`로 그 열 기준 정렬한다(오름, 내림, 원래 순서). 보는 순서만 바뀌고 파일은 그대로다.
- 표가 아닌 줄은 표 위에 설명으로 그대로 보여 준다.

## 8-4. 버튼 (`actions`)

에이전트가 버튼을 달아 두면 사용자가 눌러서 실행한다. 버튼마다 하는 일은 에이전트가 정한다.

```markdown
---
type: actions
title: 자주 쓰는 동작
---
- 테스트 돌리기
  run: go test ./...
- 방금 변경 리뷰 요청
  ask: 방금 바꾼 내용을 리뷰하고 보드에 결과를 올려 줘
```

- 목록 항목이 버튼이고, 그 아래 들여쓴 `run:` 또는 `ask:` 줄이 하는 일이다. 버튼은 테두리가 있는 상자로 그리고, `enter`·`space`·클릭으로 누른다.
- **`run:`** 은 프로젝트 폴더에서 셸 명령을 실행한다. 출력은 `<노트 이름>-output.md` 로그 노트에 쌓이고 그 노트가 열린다. 실행 중에는 버튼에 표시가 돌고, 끝나면 성공·실패가 남는다.
- **`ask:`** 는 에이전트에게 보내는 말이다. `.stickypane/inbox.md`에 시각과 함께 한 줄로 쌓인다. 에이전트는 `stickypane wait --inbox`로 기다리다가 바로 받거나, 다음 차례에 `inbox.md`를 읽는다.
- **입력을 받아 보내기(submit)**: `run:`이나 `ask:`에 `{input}`이 들어 있으면, 버튼을 눌렀을 때 한 줄 입력창이 뜨고 입력한 글이 그 자리에 들어간다. 글을 써서 에이전트에게 보내거나(`ask: {input}`) 스크립트에 넘기는(`run: gh issue create --title "{input}"`) 용도다. `run:`에 넣을 때는 셸에서 안전하도록 따옴표 처리한다.
- 쉬고 있는 에이전트를 버튼으로 깨우려면 `run:`에 에이전트 실행 명령을 단다(예: `run: claude -p "..."`). 도구가 특정 에이전트를 알 필요는 없다.
- **안전**: `run:` 명령은 노트 파일에 적힌 글자가 그대로 실행된다. 그래서 명령이 처음 눌리거나 내용이 바뀌었을 때는 명령 전문을 보여 주고 확인을 받는다. 확인한 명령은 그 실행 동안 기억한다.

## 8-5. 흐름 (Mermaid 블록) — 구현됨

처음에는 D2 문법의 `diagram` 위젯으로 설계했으나, 에이전트가 설명할 때 이미 Mermaid를 쓰므로 **일반 노트 안의 ` ```mermaid ` 블록을 그 자리에서 그림으로 그리는 것**으로 바꿨다. 별도 위젯도, 외부 명령도 필요 없다.

```
┌───────┐     ┌──────┐     ┌───────┐
│ agent ├────►│ file ├────►│ board │
└───────┘     └──────┘     └───────┘
```

- 그리기는 [mermaid-ascii](https://github.com/AlexanderGrooff/mermaid-ascii)(MIT)를 라이브러리로 넣어 쓴다. 순서도(`graph`, `flowchart`)와 시퀀스 다이어그램을 그린다.
- 그릴 수 없는 블록(지원하지 않는 종류, 문법 오류, 닫히지 않은 블록)은 원문을 그대로 보여 준다.
- 알려진 한계: 되돌아가는 화살표가 많은 그래프는 선이 겹쳐 읽기 어렵다. 화면보다 넓은 그림은 잘린다(가로 스크롤은 아직 없다).

## 8-6. 수치 (`chart`) — 구현됨

에이전트가 적은 숫자를 그림으로 보여 준다.

```markdown
---
type: chart
title: 패키지별 테스트 수
view: bar
---
app: 61
board: 31
checklist: 21
store: 16
```

- `이름: 숫자` 줄이 자료다. `view`가 그리는 방식을 정한다: `bar`(가로 막대, 기본), `spark`(한 줄 추이), `heat`(달력 잔디. 이름이 `2026-10-01` 같은 날짜여야 한다).
- 자료가 아닌 줄은 그림 위에 설명으로 그대로 보여 준다.
- 숫자는 `1,200`, `2_400`, `300.5`처럼 적어도 되고 적은 그대로 보여 준다. 줄 앞의 `- `, `* `는 무시한다.
- `heat`의 농도는 최댓값 대비 비율이 아니라 순위로 정한다. 하루만 유난히 큰 날이 있어도 나머지 날이 모두 가장 옅은 칸이 되지 않는다. 값이 0인 날은 `·`, 값이 없는 날은 빈칸이다. 폭이 좁으면 최근 주만 보여 준다.

## 8-7. 사용량 (`usage`)

에이전트가 쓴 토큰을 날짜별 잔디와 합계로 보여 준다. 이 위젯은 에이전트가 숫자를 적는 것이 아니라 도구가 직접 읽는다.

```markdown
---
type: usage
title: Claude 사용량
scope: project
weeks: 12
---
```

```
        7월        8월          9월         10월
 월  ░ ░ ▒ ░ ▓ ▒ ░ ▒ ▓ █ ▒ ░
 수  ░ ▒ ▒ ▓ █ ▒ ▒ ▓ █ █ ▓ ▒
 금  ░ ░ ▒ ▒ ▓ ░ ▒ ▒ ▓ ▓ ▒
 오늘 출력 84만 · 입력 12만 · 캐시 읽기 5,210만      이번 주 출력 310만
```

- `scope: project`는 이 프로젝트의 세션만, `all`은 전부다. `weeks`는 잔디에 보이는 주 수다.
- 앞선 설계가 뺐던 "에이전트 세션 감시"와는 다르다. 세션을 제어하거나 내용을 보여 주지 않고, 사용량 숫자만 더한다.

### 추출 구조 (ccusage를 따른다)

사용량 도구 가운데 소스를 읽을 수 있는 [ccusage](https://github.com/ryoppippi/ccusage)의 구조를 그대로 따른다(2026-10-01 판을 읽고 확인). 에이전트가 자기 세션 기록을 로컬 파일로 남기고, 도구는 그 파일을 읽기만 한다. 에이전트 쪽 설정이나 API 호출은 없다.

```
에이전트별 어댑터  →  공통 사용량 항목  →  중복 제거  →  날짜별 합계  →  잔디·합계
(claude, codex)      (시각, 세션, 프로젝트,
                      모델, 토큰 넷)
```

**공통 사용량 항목**: 시각, 세션 ID, 프로젝트, 모델, 그리고 토큰 넷(입력, 출력, 캐시 생성, 캐시 읽기).

**Claude Code 어댑터**

| 항목 | 규칙 |
|---|---|
| 찾는 곳 | `CLAUDE_CONFIG_DIR`(쉼표로 여러 개)가 있으면 그것만. 없으면 `$XDG_CONFIG_HOME/claude`(기본 `~/.config/claude`)와 `~/.claude` 둘 다. 각 폴더의 `projects/` 아래 `*.jsonl`을 하위 폴더까지 전부 |
| 프로젝트 | `projects/` 바로 아래 폴더 이름 |
| 읽는 줄 | `message.usage`가 있는 줄. `timestamp`, `sessionId`, `requestId`, `message.id`, `message.model` |
| 토큰 | `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens` |
| 중복 제거 | `requestId`가 있으면 `message.id` + `requestId`가 같은 것은 세션이 달라도 하나로 센다. Claude Code가 한 응답을 여러 세션 기록에 복사하기 때문이다. `requestId`가 없으면 `message.id` + 세션 + 시각으로 본다 |
| 곁가지 기록 | `isSidechain: true`인 줄이 부모 대화의 응답을 되풀이한 것이면 뺀다 |
| 깨진 줄 | 건너뛴다 |

**Codex 어댑터**

| 항목 | 규칙 |
|---|---|
| 찾는 곳 | `${CODEX_HOME:-~/.codex}/sessions/`와 `archived_sessions/` 아래 `*.jsonl`. 같은 상대 경로가 둘 다 있으면 `sessions/` 쪽 |
| 읽는 줄 | `type`이 `event_msg`이고 `payload.type`이 `token_count`인 줄 |
| 토큰 | `payload.info.last_token_usage`가 그 차례의 증가분이다. 누적값(`total_token_usage`)만 있으면 앞의 누적값을 빼서 증가분을 구한다. `input_tokens`, `cached_input_tokens`, `output_tokens` |
| 모델 | `turn_context`의 모델 |
| 되풀이 | 하위 에이전트 기록은 부모의 이력을 앞에 되풀이하므로 그 구간은 세지 않는다 |

**처음 버전의 범위**

- 지원하는 에이전트는 Claude Code와 Codex다. ccusage는 그 밖에 OpenCode, Amp, Gemini 등 열여덟 가지를 어댑터로 지원한다. 같은 방식으로 어댑터 하나가 파일 하나인 구조로 두어 나중에 더한다.
- 토큰 수만 보여 준다. 비용은 모델별 가격표가 있어야 하고(ccusage는 models.dev와 LiteLLM의 가격표를 실행 파일에 넣어 둔다), 가격표를 계속 갱신해야 해서 넣지 않는다. 기록에 `costUSD`가 들어 있으면 그 값만 더해 보여 준다.
- 파일이 크므로 파일별 합계를 수정 시각·크기와 함께 기억해 두고, 바뀐 파일만 다시 읽는다. 읽기는 화면을 막지 않게 뒤에서 한다.
- 읽지 못한 파일과 건너뛴 줄 수를 위젯 아래에 보여 준다.

## 8-8. 명령줄과 MCP

파일을 직접 고치는 것이 여전히 기본 계약이다. 명령줄과 MCP는 같은 파일을 다루는 얇은 껍데기이고, 파일 편집이 불편한 에이전트나 스크립트를 위한 선택지다.

**명령**

| 명령 | 하는 일 |
|---|---|
| `stickypane list [--json]` | 노트 목록: 파일 이름, 제목, 모양, 열림, 크기, 고정 |
| `stickypane show <이름>` | 노트 파일 내용을 그대로 출력 |
| `stickypane write <이름> [--type T] [--title X] [--open] [--size S]` | 표준 입력을 본문으로 노트를 만들거나 통째로 바꾼다 |
| `stickypane answers <이름> [--json]` | 폼의 답을 질문별로 출력 |
| `stickypane wait <이름> [--timeout 5m] [--json]` | 폼의 버튼이 눌릴 때까지 기다렸다가 답을 출력. 시간 초과는 종료 코드 3 |
| `stickypane mcp` | 표준 입출력으로 MCP 서버를 띄운다 |

`<이름>`은 `.md`를 붙이지 않아도 된다. 폴더 구분자가 들어간 이름은 거부한다.

**MCP 도구**: `list_notes`, `read_note`, `write_note`, `read_answers`, `guide`(안내문). 명령과 같은 일을 한다.

**에이전트가 더 쉽게 고치도록** 노트를 통째로 다시 쓰지 않는 명령 둘을 더한다(다음 단계에서 구현).

| 명령 | MCP 도구 | 하는 일 |
|---|---|---|
| `stickypane set <이름> open=true cols=6 ...` | `set_keys` | 머리말 키만 고친다. 본문과 다른 키는 그대로 둔다 |
| `stickypane append <이름>` | `append_note` | 표준 입력을 본문 끝에 덧붙인다. 로그와 체크리스트에 쓴다 |

둘 다 보드의 수정과 같은 쓰기 규칙(파일을 새로 읽어 적용하고 한 번에 교체)을 따르므로, 사용자가 보드에서 고친 내용을 지우지 않는다.

```bash
claude mcp add stickypane -- stickypane mcp
```

`write`와 `write_note`는 노트를 통째로 바꾼다. 에이전트가 파일을 직접 덮어쓰는 것과 같아서, 그사이 사용자가 보드에서 고친 내용이 있으면 사라진다. 그래서 안내문은 "고치기 전에 다시 읽는다"를 그대로 요구한다.

## 9. 친절하게 만들고 바꾸기

- **말로 만든다.** 에이전트 안내문에 `open`, `size`, `form`을 더한다. "이슈를 칸반으로 크게 띄워 줘"라고 하면 에이전트가 모양과 크기와 열림 상태를 정해서 쓴다.
- **화면에서 고른다.** `a`를 누르면 모양 목록이 나오고, 고르고 있는 모양의 예시가 옆에 그려진다. 제목만 입력하면 된다. 만든 노트는 열린 상태다.
- **만든 뒤에 키로 바꾼다.**

| 키 | 동작 | 파일에 일어나는 일 |
|---|---|---|
| `o` | 열기/닫기 | `open` 변경 |
| `+` `-` | 크기 키우기/줄이기 | `size` 변경 |
| `t` | 모양 바꾸기 (예시를 보며 고름) | `type` 변경. 본문은 그대로 두고, 새 모양에 맞지 않는 줄도 숨기지 않는다 |
| `c` `p` `R` `x` `D` `e` | 색, 고정, 제목, 떼어 내기, 삭제, 편집 | 앞선 문서와 같다 |

사람이 머리말을 직접 타이핑할 일은 없다.

## 10. 정렬

파일은 건드리지 않고 보는 순서만 바꾼다.

- **노트 순서**: `s`로 이름순(기본), 최근 바뀐 순을 오간다. 고정한 노트는 항상 먼저다.
- **checklist**: 열린 체크리스트에서 `s`를 누르면 남은 항목을 먼저 보여 준다. 다시 누르면 파일 순서로 돌아온다.
- **table**: 고른 열 기준으로 정렬한다(8-3절).
- **board**: 카드 순서는 파일 순서 그대로다. 순서를 바꾸는 것은 `J` `K`로 파일을 고치는 동작이다.

## 13. 구현 순서

단계마다 쓸 수 있는 상태로 끝난다. 2026-10-02 기준 진행 상황을 함께 적는다.

1. **화면 뒤집기** (끝남): 제목 줄, 열림 상태, 크기에 따른 배치, 자르지 않는 그리기, 열린 노트 안에서의 조작, `o` `+` `-`, 크게 보기, 예시가 보이는 모양 고르기.

3. **그림과 수치** (끝남): 노트 안의 Mermaid 블록, `chart`(`bar`, `spark`, `heat`).
4. **묻기** (끝남): `form`, `answers`, `wait`, `read_answers`.
5. **시키기**: `actions` 버튼(`run:`, `ask:`, `{input}`), `inbox.md`. 폼의 버튼에도 같은 줄을 달 수 있게 한다.
6. **크기와 마우스**: 상하좌우 크기 조절(`cols`, `rows`), 클릭·휠·끌기.
7. **쉽게 고치기**: `set`, `append` 명령과 MCP 도구, 로그의 `file:` 따라가기.
8. **상태 줄과 페이지 뷰**: `status`, 제목 단위 넘기기, 이름으로 골라 띄우기.
9. **구조·비교**: `tree`, `table`, 정렬(`s`), 모양 바꾸기(`t`).
10. **사용량**: `usage` 위젯(8-7절의 추출 구조).

안내문은 여섯 모양을 담고 43줄이다(상한 45줄). 모양이 더 늘면 "하고 싶은 말 → 위젯" 표 하나만 싣고, 위젯별 형식은 `stickypane guide <위젯>`으로 따로 내보내 에이전트가 필요할 때만 읽게 한다.

## 14. 검토할 때 봐 주실 결정

- **열림 상태를 노트 파일의 머리말에 쓴다.** 열고 닫을 때마다 파일이 바뀌지만, 에이전트가 "사용자가 무엇을 보고 있는지"를 노트만 읽어 알 수 있다. 별도 상태 파일을 두지 않는다.
- **정렬은 보는 순서만 바꾼다.** "정렬"을 순서 정렬로 읽었다. 창을 가지런히 맞추는 배치 정렬을 뜻하셨다면 5절의 격자 배치가 그 역할이다.
- **`wait` 명령 하나를 더한다.** "노트 조작 명령은 만들지 않는다"는 범위는 유지하고, 읽고 기다리는 명령만 예외로 둔다.
- **카드 끌어 옮기기는 뒤로 미룬다.**
- **위젯은 열한 가지다.** `note`, `board`, `checklist`, `log`, `chart`, `form`, `status`, `tree`, `table`, `actions`, `usage`. "에이전트가 하고 싶은 말" 표에 빈 줄이 생길 때만 더한다. diff, 달력, 이미지는 넣지 않았다.
- **버튼의 `run:`은 노트에 적힌 명령을 실행한다.** 에이전트가 쓴 파일이 곧 실행할 명령이 되므로, 처음 누르거나 내용이 바뀐 명령은 전문을 보여 주고 확인을 받는다.
- **그림은 Mermaid 블록을 실행 파일 안에서 그린다.** 처음 결정(`d2` 명령이 있을 때만 그린다)을 뒤집었다. 외부 명령을 깔 필요가 없고 에이전트가 평소 쓰는 문법이 그대로 그림이 되는 쪽이 "설정 없이 쓴다"는 원칙에 맞다. 대신 의존성이 하나 늘었다.
- **`choice`와 버튼 달린 문서를 `form` 하나로 합쳤다.** 선택지만 있는 폼이 곧 `choice`다.
- **`usage`는 Claude Code의 세션 기록 형식에 의존한다.** 형식이 바뀌면 이 위젯만 깨진다. 읽지 못한 파일은 건너뛰고 몇 개를 건너뛰었는지 보여 준다.
- **상태 줄은 에이전트가 직접 쓴다.** 훅으로 자동 수집하지 않는다. 에이전트가 안내문을 따라 `status` 노트를 갱신해야 하므로, 빼먹으면 줄이 낡는다. 이전 wezterm 시도의 "에이전트 부담" 문제가 여기서 다시 생길 수 있어서, 써 보고 판단한다.
