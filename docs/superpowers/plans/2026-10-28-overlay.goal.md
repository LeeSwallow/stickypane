## 절대 규칙

- 본체 모듈에 새 Go 모듈을 더하지 않는다. SQLite·Wails·npm은 `overlay/` 안에만.
- 노트 변경은 `doc.Op` → `store.Apply`로만. 앱은 bridge 밖에서 노트를 읽거나 쓰지 않는다.
- 레지스트리 폴더는 `~/.stickypane/`(`~/.sticky` 아님 — `store.Find`와 충돌). 폴더가 없으면 본체는 아무것도 기록하지 않는다.
- 네트워크 listener를 열지 않는다. 앱 CSP는 외부 URL을 막는다. 글꼴·렌더러는 번들.
- 랜딩·설명 화면을 만들지 않는다(R-32). 홈은 세션 목록, 비면 빈 상태 한 장.
- `init`은 TTY에서 사람이 직접 실행할 때만 묻는다. 에이전트·앱·자동 init이 멈추면 안 된다.
- 반복 애니메이션 금지. `prefers-reduced-motion`이면 opacity만.
- 시각은 `internal/when`으로만 쓴다.
- 커밋: Conventional Commits, 하나에 한 변경, `(#10)`, AI 도구 이름·`Co-Authored-By` 금지(`git config core.hooksPath .githooks`). **push·merge·tag·브랜치 삭제는 하지 않는다.**
- 이 레포에서는 `moa:*` 스킬과 `moa-transition`을 쓰지 않는다.
- 설계와 어긋나는 결정이 필요하면 코드를 바꾸기 전에 멈추고 보고한다. 설계를 조용히 바꾸지 않는다.

## 환경

- 브랜치: `feat/10-desktop-overlay` (이미 있음, 설계 문서 커밋 포함). 그 위에서 작업한다.
- Go 1.27, Node 22(`~/.local/bin/node`). 시작할 때 본체 게이트가 통과하는지 확인한다.
- **사람의 승인이 필요한 설치**(자동 모드가 외부 코드 내려받기를 막는다). 앱 계획 A1 전에 사용자에게 요청한다:
  - `go install github.com/wailsapp/wails/v3/cmd/wails3@<고정 버전>`
  - `overlay/frontend`의 `npm install`(계획의 Tech Stack 패키지만)
  - `overlay/go.mod`의 `go get github.com/wailsapp/wails/v3@<버전> modernc.org/sqlite@<버전>`
  - 고른 정확한 버전과 이유를 `docs/overlay/07-requirements-log.md`의 "실행 기록"에 남긴다.

## 작업 방식 (Task마다 반복)

1. 실패하는 테스트를 먼저 쓴다. 계획에 적힌 테스트 이름과 단언을 그대로 쓴다.
2. 실행해서 **예상한 이유로** 실패하는지 확인한다.
3. 최소 구현을 한다.
4. 해당 패키지, 그다음 전체 게이트를 실행한다.
   - 본체: `go vet ./... && go test -race ./... && test -z "$(gofmt -l .)"`
   - 앱(A1 이후): `cd overlay && go vet ./... && go test -race ./... && npm --prefix frontend run check && npm --prefix frontend test && sh scripts/licenses.sh`
5. 커밋한다.
6. Task마다 새 검토 에이전트에게 diff와 계획의 해당 Task, 관련 설계 절을 주고 검토를 받는다. 지적은 고친 뒤 다음 Task로 넘어간다.
7. 본체 계획이 끝나면(Task 14 뒤) 브랜치 전체 검토를 한 번 받는다. 앱 계획 끝(A13 뒤)에 다시 한 번.
