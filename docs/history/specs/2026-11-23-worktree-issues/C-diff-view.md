# proposal: 워크트리가 바꾼 파일과 코드를 보드에서 쪽으로 넘겨 본다

라벨: proposal, needs triage
상위 이슈: 총괄 이슈 (워크트리를 보드에서 다룬다)
선행: A, B

## 문제

워크트리가 무엇을 바꿨는지 보려면 보드를 떠나 `git diff`를 쳐야 한다.
에이전트가 워크트리 서넛에서 일하면 사용자는 이 셋을 알 수 없다.

- 워크트리마다 파일이 몇 개 바뀌었는지.
- 두 워크트리가 같은 파일을 고치는지. 모르면 병합 충돌로 알게 된다.
- 파일마다 코드가 어떻게 바뀌었는지.

필요한 것은 보드 안에서 바뀐 파일 목록과 파일별 코드 변경을 보는 화면이다.
워크트리 추적(A)과는 따로 쓸 수 있어야 한다. 레지스트리를 꺼도 이 화면은 돈다.

## 제안

`diff`라는 보기 전용 shape 하나. 읽기만 하고 노트 파일에는 쓰지 않는다.
보드가 적는 것은 사용자가 고른 워크트리와 기준(base)뿐이고, 그것도 그 노트의 `sticky.json` 항목에만 적는다.
git에서 화면에 띄울 때 읽고 저장하지 않으니 저장소와 어긋날 수 없다.

두 단계로 나눈다. 1단계만으로도 쓸모가 있어야 한다.

### 1단계: 바뀐 파일, 겹침 경고, 풀 리퀘스트 한 줄

첫 쪽은 워크트리 목록이다. 하나를 고르면 그 워크트리의 바뀐 파일 목록이 나온다.

```
┌ diff · 워크트리 고르기 ──────────────────────────── 1/8 ┐
│ ▸ feat/chart-ui        main…  7개  +128 −41   열림      │
│   refactor/widget      main…  3개   +22 −19   열림      │
│   feat/api-widget      main…  —  병합됨       닫힘      │
│                                                         │
│ j k 고르기 · enter 열기 · b 기준 바꾸기 (main)          │
└─────────────────────────────────────────────────────────┘
        enter │  (2쪽부터 8쪽은 feat/chart-ui 의 파일들)
              ▼
┌ feat/chart-ui · diff ─────────────────────────────── 3/8 ┐
```

- 목록은 `git worktree list --porcelain`으로 읽는다. 레지스트리(A)를 거치지 않으므로 A가 꺼져 있어도 된다.
  사라진 워크트리는 A가 남긴 폴더가 있을 때만 닫힘으로 보인다.
- 행의 수는 `git diff --numstat <base>...HEAD`로 읽고, 화면에 보이는 행만 읽는다.
- 워크트리마다 `git diff --name-only <base>...HEAD`를 읽어, 두 곳 이상이 바꾼 파일에 경고를 붙인다.

```
│ ⚠ internal/core/widget/chart/view.go                    │
│   feat/chart-ui · refactor/widget 둘 다 바꿈            │
```

- 목록 아래에 풀 리퀘스트 한 줄을 둔다. 제목과 상태(열림, 병합됨)만 둔다.
  `gh pr view --json title,state,url`을 쓸 수 있는지, 없는 환경에서 줄을 어떻게 감출지는 (확인 필요).
  `gh`가 없으면 줄을 비운다.

### 2단계: 파일 하나가 한 쪽, 변경 본문

골라 연 워크트리의 바뀐 파일이 쪽이 된다. 쪽은 `,` `.`로 넘긴다(B의 `paging: single`).
쪽에는 파일의 변경이 그려지고, 추가한 줄과 지운 줄은 색이 다르다.

```
┌ feat/chart-ui · diff ───────────────────────────── 3/8 ┐
│ M internal/core/widget/chart/view.go  +12 −3            │
│ @@ -41,7 +41,9 @@ func (m Model) bar(…                  │
│   width := m.width                                      │
│ - gap := 1                                              │
│ + gap := max(m.width/40, 1)                             │
└─────────────────────────────────────────────────────────┘
```

- 큰 diff는 쪽마다 읽는다. 보이는 쪽만 `git diff <base>...HEAD -- <file>`로 읽고,
  쪽이 창보다 길면 `j` `k`로 스크롤한다.
- 이진 파일은 줄 없이 `binary` 한 줄만 보인다. `--numstat`이 `-  -`를 주면 이진으로 본다.
- 이름이 바뀐 파일은 `R old → new`로, 모드만 바뀐 파일은 `mode 100644 → 100755`로 보인다.
- 끝에 줄바꿈이 없으면 git이 붙이는 `\ No newline at end of file`을 그대로 보인다.
- 커밋하지 않은 변경과 추적하지 않는 파일은 `git status --porcelain`으로 읽어 목록 끝에 따로 묶는다.

```mermaid
flowchart LR
  pick["1쪽: 워크트리 목록<br/>고른 값은 sticky.json"] --> names["어댑터: 이름과 수<br/>--name-status, --numstat"]
  names --> list["파일 목록 쪽들"]
  list --> body["어댑터: 파일 하나의 diff<br/>보이는 쪽만"]
  body --> parse["core: unified diff 해석<br/>파일 → 덩어리 → 줄"]
  parse --> view["book, paging: single"]
```

### 책을 쓰는 방식

diff는 책이다. 책이 이미 하는 일은 그대로 쓰고, 새로 하는 일은 하나로 줄인다.

| | 책이 이미 하는 것 | 새로 하는 것 |
| --- | --- | --- |
| 페이지 | 테두리의 `n/N`, `,` `.`로 이동 | 페이지를 파일 대신 원천(source)에서 받는다 |
| 보기 | 한 페이지씩 보기(#142)와 이어서 보기 | diff 책의 기본값을 한 페이지씩으로 둔다 |
| 설정 | 크기, 열림, 고정, 색을 `sticky.json`에 노트별로 | 고른 워크트리와 기준을 같은 항목에 |
| 데스크톱 | 책 컴포넌트가 페이지를 그린다 | 변경 파일 페이지의 그림(`Diff.svelte`) |
| 섞인 shape | 페이지마다 자기 shape | 목록 페이지와 파일 페이지가 서로 다른 shape |

- **페이지 구성.** 첫 페이지는 워크트리 목록이고, 다음부터 바뀐 파일이 한 페이지씩이다. 페이지 이름은 파일 경로다.
- **사용자의 페이지가 함께 산다.** 사용자가 `m`이나 `mv`로 diff 책에 옮겨 넣은 노트(리뷰 메모 등)는 원천이 낸 페이지 뒤에 붙는다.
  책 안에 바로 새 페이지를 더하는 길은 #148에서 만든다. 리뷰하며 메모를 붙이는 쓰임이 된다.
  원천이 낸 페이지는 읽기 전용이다. 옮기거나 지우려 하면 거절한다 (확인 필요).
- **워크트리 책과의 관계.** 워크트리 책(#141의 `worktrees/<이름>/`)과 diff 책은 책 둘이다. 책 안에 책은 만들 수 없다 (확인 필요).
  둘은 `[[링크]]`로 잇는다. 워크트리 책의 `00-개요.md`에 diff 책으로 가는 링크가 있고, 열면 같은 워크트리가 골라져 있다.
- **원천은 어디서 선언하나.** 탭의 폴더는 자기 `sticky.json`을 가질 수 있다. 그 폴더가 diff 책임을 거기에 적는 것이 가장 가깝다 (확인 필요).
  없으면 책은 지금처럼 폴더의 파일만 페이지로 삼는다. 기존 보드는 달라지지 않는다.

### 워크트리 고르기

- 고르는 사람은 사용자다. 고른 워크트리와 기준은 이 노트의 `sticky.json` 항목에 보드가 적는다.
  사용자가 쪽의 크기나 열림을 정할 때와 같다.
- 고른 값이 없으면 보드를 시작한 워크트리가 기본이다.
- 노트의 front matter에 워크트리 이름을 적어 고정할 수도 있다. 고정하면 목록 쪽은 건너뛴다.
- `enter`와 `b`가 책의 쪽에서 비어 있는 키인지는 (확인 필요).

### 기준(base) 규칙

기준이 늘 `main`은 아니다.

1. 노트나 `sticky.json`에 기준이 적혀 있으면 그것을 쓴다.
2. 없으면 저장소 기본 브랜치와 워크트리 HEAD의 merge-base(`git merge-base`).
3. 기본 브랜치를 찾지 못하면 목록에 기준 없음이라 적고, `b`로 사용자가 고르게 한다.

기본 브랜치는 `git symbolic-ref refs/remotes/origin/HEAD`로 읽는다. 원격이 없는 저장소에서의 동작은 (확인 필요).
Claude Code의 `worktree.baseRef: head`처럼 현재 HEAD에서 갈라진 워크트리도 규칙 2로 맞는 기준을 얻는다.
이 설정 이름은 조사 기록에서 가져왔고 직접 확인하지 않았다 (확인 필요).

## 대안

핵심 질문은 쪽이 파일이 아닌 책을 어떻게 만드느냐다. 지금 책의 쪽은 폴더의 파일이다.
`internal/surface/app/reload.go`가 `store.Note`의 `Pages`로 쪽을 만든다.

| | 파생 파일 | 쪽의 원천(source) |
| --- | --- | --- |
| 방식 | 유스케이스가 파일마다 `.diff` 파일을 워크트리 폴더에 쓴다 | 책이 파일 대신 쪽을 내놓는 원천에서 쪽을 받는다 |
| 책 코드 | 그대로 | 쪽을 받는 길을 새로 낸다 (확인 필요) |
| 저장 | diff가 파일로 남고 낡는다 | 남는 것이 없다 |
| 쓰기 규칙 | 보드가 만든 파일이 `.sticky/` 안에 쌓인다 | 노트 파일을 건드리지 않는다 |
| 큰 diff | 만들 때 전부 읽는다 | 보이는 쪽만 읽는다 |

권장은 쪽의 원천이다. 이유는 셋이다.

1. 파생 파일은 저장소와 어긋난다. 커밋 하나에도 낡는다.
2. 큰 diff를 쪽마다 읽으려면 미리 만들어 두는 방식은 맞지 않는다.
3. 이 보드에서는 파일이 곧 노트다. 보드가 만든 파생 파일을 사용자가 지우고 고치게 된다.

대신 값을 치른다. 책과 `store.Note`가 파일 말고 다른 쪽 공급원도 아는 구조가 되어야 하고,
그 변경은 `surface`와 `adapter/store`에 걸친다. 이 변경이 책의 다른 동작(`link`, 순서, 쪽 이름)을 깨지 않는지는 (확인 필요).
계획 단계에서 책이 쪽을 받는 길을 먼저 시험하고, 막히면 파생 파일로 물러난다.

## 바뀌는 것

AGENTS.md의 shape 규칙대로 `internal/core/widget/diff/` 한 패키지를 만든다. 보기 전용이라 `html`처럼 `ops.go`와 `events.go`는 주석만 둔다.

| 파일 | 내용 |
| --- | --- |
| `kind.go` | `widget.Kind`: 이름 `diff`, 아이콘, 키, 소개, 예시, `Command`, `Usage` |
| `format.go` | unified diff의 문법: 헤더, `@@` 덩어리, `+` `-` 줄, `Binary files`, `\ No newline`, `rename from/to`, `old mode/new mode` |
| `model.go` | 읽는 쪽: 파일 → 덩어리 → 줄. 화면 상태는 없다 |
| `ops.go` | 주석만. diff에서 바꿀 것이 없다 |
| `view.go` | 그리기: 추가 줄 초록, 지운 줄 빨강, 덩어리 머리글. lipgloss는 여기서만 쓴다 |
| `events.go` | 주석만 |

- `internal/core/kinds`의 `Default`에 한 줄을 더한다. `TestEveryKindKeepsTheContract`가 통과해야 한다.
- 해석기는 표준 라이브러리만 쓴다. core는 git을 실행하지 않고 받은 글만 해석한다.
- 새 어댑터 `internal/adapter/gitread`(이름은 (확인 필요))는 git을 실행해 글을 돌려준다.
  `os/exec`는 어댑터에서만 쓴다. 화면 폭이나 색은 모른다.
- 겹침 계산과 기준 정하기는 사용자의 선택과 얽힌 규칙이라 유스케이스에 둔다.
  `internal/usecase/diffbook`(이름은 (확인 필요))이 어댑터를 불러 목록과 쪽 내용을 만든다.
- `internal/adapter/store`의 `View`에 워크트리와 기준 두 필드를 더한다. 기존 `sticky.json`은 모르는 키를 보존하므로 이전 보드는 안전하다.
- `internal/surface/app`은 쪽의 원천을 책에 연결하고 `enter`와 `b`를 처리한다.
- `docs/architecture.md`의 순위표에 새 패키지마다 한 줄을 더한다. `internal/layers`가 순위를 검사한다.

## 하지 않을 것

- 함수 단위 보기. 언어마다 해석기가 필요하다.
- diff 안에서 노트나 파일을 고치는 일. 읽기 전용이다.
- 워크트리를 만들고, 지우고, 합치는 일.
- 코드 리뷰의 댓글, 승인, 병합.
- 워크트리 추적(A)에 기대는 일. 이 기능은 A 없이도 돈다.
- 큰 diff를 한꺼번에 읽는 일.
- core에서 git을 실행하는 일.

## 열린 질문

1. 책이 쪽을 파일이 아닌 원천에서 받을 수 있는가 (대안 절 참고). (확인 필요)
2. 목록은 diff 책의 첫 쪽인가, form 같은 별도 shape인가. 첫 쪽이 더 간단하다고 본다.
3. `enter`와 `b`가 책의 쪽에서 비어 있는가. (확인 필요)
4. 풀 리퀘스트 한 줄에 `gh`를 써도 되는가, 쓴다면 없는 환경에서 어떻게 감추는가. (확인 필요)
5. 커밋하지 않은 변경과 추적하지 않는 파일을 목록 끝에 묶어도 되는가.
6. 원격이 없는 저장소와 분리된 HEAD(detached)에서 기준은 무엇인가. (확인 필요)
7. `.worktreeinclude`로 `.sticky/`가 복사된 워크트리에서 고른 값이 낡은 사본을 읽지 않는가. (확인 필요)
8. 고른 워크트리가 사라지면 목록으로 돌아가는가, 닫힘으로 남기는가.
9. 수천 줄 diff에서 쪽 하나를 읽는 시간의 상한, 그리고 넘으면 보일 문구.

## 테스트 계획

해석기를 먼저 만들고, 실제 `git diff` 출력을 고정 파일(fixture)로 둔다.
fixture는 `internal/core/widget/diff/testdata/`(확인 필요)에 두고, 원본 diff와 기대하는 해석을 나란히 둔다.

| fixture | 검사하는 것 |
| --- | --- |
| 이름 바꿈 | `rename from` `rename to`와 유사도. 내용 변경이 있는 경우와 없는 경우 |
| 이진 파일 | `Binary files a/x and b/x differ`가 `binary` 한 줄이 되고, `--numstat`의 `-  -`와 같이 이진으로 본다 |
| 끝에 줄바꿈 없음 | `\ No newline at end of file`이 앞 줄에 붙고 줄 수를 어긋나게 하지 않는다 |
| 모드 변경 | 내용 없이 `old mode`/`new mode`만 있는 파일, 내용도 바뀐 파일 |
| 큰 diff | 수천 줄. 한 쪽만 읽고 나머지는 읽지 않는다. 쪽을 넘겨도 메모리가 늘지 않는다 |
| 새 파일, 지운 파일 | `/dev/null` 쪽 처리 |
| 빈 diff | 바뀐 파일이 없을 때 빈 목록 한 줄 |

그 밖의 검사:

- 각 폭(1, 7, 20, 80)에서 줄이 폭을 넘지 않는다. `TestEveryKindKeepsTheContract`가 본다.
- 어댑터는 임시 저장소에서 `git`을 실제로 돌린다. CI에 git이 있는지, 워크트리를 만들 수 있는지는 (확인 필요).
- 기준 규칙 1, 2, 3과 기준 없음.
- 겹침: 두 워크트리가 같은 파일을 바꿀 때와 아닐 때.
- 고른 값이 `sticky.json`에 저장되고 다시 읽힌다. 모르는 키가 보존된다.
- 고른 값이 없으면 보드를 시작한 워크트리가 쓰인다.
- `internal/layers`: 새 패키지의 층과 순위가 맞고 core가 `os/exec`를 가져오지 않는다.
- 이 저장소의 마지막 커밋 diff가 실제 앱에서 맞게 보이는지 캡처로 확인한다.

## 에이전트 브리프

- **목표:** 워크트리를 고르고, 바뀐 파일을 쪽으로 넘기며, 파일의 변경을 그려 본다. 읽기 전용.
- **먼저 읽을 것:** `docs/architecture.md`의 "A shape of note"와 층 절, `internal/core/widget/html`과
  `internal/core/widget/logview`(보기 전용 shape), `internal/surface/app/book.go`와 `reload.go`,
