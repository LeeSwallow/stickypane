## 3.2 브랜드: 아이콘

[사용자 결정] 아이콘은 **파랑·빨강·노랑 메모지 세 장을 겹친 모양**이다. 크레용 빗금 채우기, 굵은 검은 외곽선, 맨 위 노랑 메모지의 말린 모서리.

- 아이콘의 문법(옅은 바탕 + 빗금 + 굵은 외곽선)이 손그림 스타일의 카드·버튼·로고에 그대로 쓰인다.
- 앱 아이콘·트레이 아이콘·창 제목줄 로고에 쓴다. 트레이(메뉴 막대)용은 단색 템플릿 이미지를 따로 만든다.
- 원본 파일 위치: `docs/overlay/assets/icon.png` (사용자가 넣는다).

## 3.3 테마: 두 축

[사용자 결정] 테마는 고를 수 있다. 축은 둘이다.

```mermaid
flowchart LR
  subgraph color["색 테마 (기존 theme 키, 터미널과 공유)"]
    c1["stickypane-dark / light"]
    c2["catppuccin-mocha / latte"]
    c3["tokyonight-night / day"]
    c4["gruvbox-dark / light"]
    c5["nord · dracula"]
  end
  subgraph style["스타일 테마 (새 style 키)"]

    s2["단정 neat"]
  end
  color --> screen["overlay 화면"]
  style --> screen
```

| 축 | 값 | 저장 | 바꾸는 곳 |
|---|---|---|---|
| 색 | 기존 10개 | `sticky.json` `"theme"` (기존) | 터미널 설정 패널, `stickypane theme`, overlay 설정 |
| 스타일 | `doodle`(기본) · `neat` | `sticky.json` `"style"` (신규) | overlay 설정, `stickypane init` |

[설계자 판단] 기본 스타일은 아이콘과 맞는 **손그림**이다. 터미널은 스타일 키를 무시한다.

| | 손그림 doodle | 단정 neat |
|---|---|---|
| 선 | rough.js(노트 0.8, 카드 1.1), 카드만 ±1.5° 기울기 (§3.11.3) | 직선, 기울기 없음 |
| 채우기 | 옅은 바탕 + 크레용 빗금(−41°) | 단색 옅은 바탕 |
| 장식 | 테이프, 손으로 그린 밑줄·형광펜·동그라미 | 없음 |
| 제목 글꼴 | Gaegu Bold | Pretendard SemiBold |

## 3.4 다크 모드와 격자 노트

[사용자 결정] 바탕은 격자 노트(모눈종이)이고, 다크 모드까지 된다(R-38).

- **모드**는 시스템 · 다크 · 라이트 세 가지다. 시스템이면 OS의 밝음·어두움(`prefers-color-scheme`)을 따르고, OS 설정이 바뀌면 바로 따라간다. 터미널의 theme `auto`와 같은 뜻이다.
- 모드는 색 테마의 **짝**으로 바꾼다: stickypane-dark ↔ light, catppuccin-mocha ↔ latte, tokyonight-night ↔ day, gruvbox-dark ↔ light. 짝이 없는 nord·dracula는 라이트 모드에서 stickypane-light를 쓴다. 사용자가 고른 테마 이름은 그대로 `theme` 키에 남고, 모드는 overlay 설정(`overlay.json`의 `mode`, 기본 시스템)이다.
- **격자**: 18px 가는 선 + 90px마다 진한 선. 선 색은 바탕과 글자 사이의 색이라 어떤 테마에서도 은은하다. 노트 메모지 안에는 격자가 없다(종이 위에 붙은 메모지).
- 다크에서 카드 글자는 진한 색(wash가 밝기 때문), 라이트에서는 `Text`. 어느 쪽이든 카드 글자(`--card-ink`)는 wash 위와 wash·빗금 50% 혼합 위에서 4.5:1이 되도록 필요한 만큼만 검정 쪽으로 어둡게 한다(`Text`가 이미 넘으면 그대로). 외곽선은 다크에서 `Base`를 55% 어둡게, 라이트에서 `Text`.
- 모든 테마 × 두 모드에서 대비 4.5:1을 자동으로 검사한다([06 §6.3](06-roadmap-and-verification.md#63-검증-게이트-모든-단계-공통)).
- 아이콘은 투명 배경이라 두 모드 모두에서 그대로 쓴다. 트레이 아이콘은 단색 템플릿 이미지(OS가 모드에 맞춰 칠한다).

## 3.4.1 색 토큰

`internal/theme`의 역할을 CSS 변수로 옮긴다. 값은 bridge가 `settings.get`으로 내려 준다. 화면은 자기 색을 갖지 않는다.

| 토큰 | 출처 | 쓰임 |
|---|---|---|
| `--base` | `Base` | 버튼 위 글자, 진한 카드 글자 |
| `--ink` | `Text` | 본문 |
| `--pencil` | `Muted` | 열 제목, 경과 시간, 보조선, 체크박스 |
| `--accent` | `Accent` | 포커스, 선택, 활성 탭 밑줄, 주 버튼 |
| `--select` | `Select` | 코드 배경, 비활성 칩 테두리 |
| `--good` / `--warn` / `--bad` / `--info` | 같은 이름 | 체크 / 정체·대기 / 오류 / 헤딩·키워드 |
| `--yellow` … `--orange` | `Notes[6]` | 노트 테두리·제목, 카드 색, 에이전트 색 |
| `--paper` | `Base`를 6% 어둡게(어두운 테마) / 50% 밝게(밝은 테마) | 창 종이 |
| `--grid` | `Base`와 `Text` 사이 7%(어두움) / 9%(밝음) | 격자 노트의 가는 선, 18px 간격 |
| `--grid-major` | `Base`와 `Text` 사이 13% / 17% | 다섯 칸(90px)마다 진한 선 |

**파생 규칙**
- 카드 바탕(wash) = 노트 색을 흰색 쪽으로 35%(어두운 테마) 또는 78%(밝은 테마). 빗금은 노트 색 그대로.
- 외곽선 = 어두운 테마는 `Base`를 55% 어둡게, 밝은 테마는 `Text`.
- **카드 글자** `--card-ink` = 다크는 `Base`를 40% 어둡게, 라이트는 `Text`. 카드 색 여섯 가지 모두에서 wash 위와 wash·빗금 50% 혼합 위의 대비가 4.5:1이 되도록 필요한 만큼만 검정 쪽으로 어둡게 한다. 모든 카드 글자는 이 토큰을 쓴다.
- **에이전트 색** = 이름을 해시해 `Notes[6]` 중 하나. 같은 이름은 어느 프로젝트에서나 같은 색. 노트의 `color` 규칙(파일 이름 해시, FNV-1a 32비트 mod 6; 고른 색 이름이 있으면 그것이 먼저)과 같은 방식이다. overlay의 @owner는 이 노트 색 해시를 쓴다. 터미널의 `NameStyle`(4가지 스타일 해시)과는 다르다.

## 3.5 글꼴

[사용자 결정] 오픈소스로 쓸 수 있는 글꼴만 쓰고, 앱에 번들한다(CSP로 외부 요청 차단).

| 역할 | 글꼴 | 라이선스 | 쓰는 곳 |
|---|---|---|---|
| 손글씨 | **Gaegu** 400/700 (JIKJI SOFT) | OFL-1.1 | 프로젝트 이름, 노트 제목, 카드, 열 제목, 배지, 주석 |
| 본문 | **Pretendard Variable** 1.3.9 | OFL-1.1 | Markdown 본문, form 선택지, 체크 항목, 칩의 설명 |
| 고정폭 | **JetBrains Mono** | OFL-1.1 | 코드, 경과 시간, 개수, 단축키 표시 |
| 고정폭 한글 | D2Coding | OFL-1.1 | 로그·코드 안의 한글 정렬이 필요할 때 fallback |

- 숫자는 `font-variant-numeric: tabular-nums`. 값이 바뀌어도 폭이 흔들리지 않는다.
- 한글 손글씨 크기는 라틴보다 1~2px 크게 보이도록 Gaegu는 본문보다 3~5px 크게 쓴다(목업 기준 제목 21px, 카드 16px, 본문 13px).
- 글꼴 라이선스 사본을 앱 번들과 `THIRD_PARTY_NOTICES.md`에 넣는다. JetBrains Mono를 수정하면 이름을 바꿔야 한다(상표).

## 3.6 창 구성

```text
┌──────────────────────────────────────────────────────────────┐
│ [로고] stickypane  ~/path            ⌥Space    [+ 생성] [📌] │  제목줄 (드래그 영역)
│ (@claude 지금 카드 4m) (@codex … 28m) (@sam …)   멈춤 1       │  Glance 줄
│ 작업  노트  기록  묻기                                         │  탭 = 폴더
│ ┌─ 노트(1) ──────────────────────────────────────────────┐   │
│ │ board: 열마다 작은 메모지 카드                            │   │  본문 = 12열 그리드
│ └────────────────────────────────────────────────────────┘   │  1 = 12열
│ ┌─ 노트(1/2) ───────────┐ ┌─ 노트(1/2) ───────────┐          │  1/2 = 6열
│ └──────────────────────┘ └──────────────────────┘          │  1/4 = 3열 … 3/4 = 9열
└──────────────────────────────────────────────────────────────┘
```

| 영역 | 규칙 |
|---|---|
| 창 | 기본 840×(화면 높이 70%), 둥근 모서리 16, 그림자. 프레임 없는 창, 제목줄이 드래그 영역 |
| 제목줄 | 로고, 프로젝트 이름(손글씨), 경로, 단축키, "+ 생성"(카탈로그), 핀 |
| Glance 줄 | board 카드의 `@이름`마다 이름표 하나(사람·에이전트를 가리지 않는다): `@이름`(에이전트 색, 손글씨) · **지금 카드** = 그 이름의 카드 중 마지막 열이 아닌 것에서 가장 최근에 움직인 것 · 경과 시간. 그런 카드가 없으면 "쉬는 중". 그 이름의 카드 중 정체(bridge Data의 `stalled`, 본체의 `stale` 설정을 따름)가 있으면 경고색 테두리. 누르면 그 이름으로 필터 |
| 탭 | 터미널과 같은 폴더 탭. 활성 탭은 손으로 그은 밑줄 |
| 본문 | 12열 그리드. 노트의 `size`는 터미널과 같은 화면 너비의 비율이다: `1/4`은 3열, `1/3`은 4열, `1/2`은 6열, `2/3`은 8열, `3/4`은 9열, `1`은 12열. 옛 이름 `page`는 `1`, `half`는 `1/2`, `card`는 카드 하나(약 300px)가 들어가는 가장 좁은 비율로 읽는다. 한 줄의 노트들은 남는 폭을 비율대로 나눈다. 순서는 터미널과 같다(고정 먼저, 파일 이름순) |
| 좁은 창 | 노트가 240px보다 좁아지는 비율은 그다음 비율을 쓴다(터미널의 20칸과 같은 규칙). 폭 720px 미만이면 모든 노트가 `1`이 되고, board는 2열로 접힌다 |

## 3.6.1 자유 캔버스와 떼어낸 노트

[사용자 결정] overlay가 켜져 있을 때 노트는 터미널의 배치와 별개로 **여기저기 붙일 수 있다**(R-39). 노트의 **내용은 같은 파일을 공유**하고, overlay에서의 **위치만** 이 컴퓨터에 따로 기억한다(R-40).

| 모드 | 모습 | 저장 |
|---|---|---|
| **캔버스**(기본) | 보드 본문이 격자 노트 캔버스가 된다. 노트(메모지)를 끌어 아무 데나 붙이고, 살짝 기운 각도와 겹침 순서(마지막에 만진 것이 위)를 기억한다. 처음 보는 노트는 그리드 자리(§3.6)에 놓인 뒤 그 자리가 기억된다. 스크롤·확대축소(⌘+휠, 50–200%) | `~/.stickypane/overlay.json`의 `projects.<경로>.places.<노트>`: `{x, y, w, h, tilt, z}` |
| **그리드** | §3.6의 2열 배치(터미널과 같은 순서·크기) | 없음(sticky.json의 size·order를 따름) |
| **떼어낸 노트** | 노트 머리의 "떼어내기"(또는 캔버스 밖으로 끌어내기) → 그 노트만 테두리 없는 작은 창이 되어 바탕화면·다른 앱 위 아무 데나 붙는다. 노트별 핀(항상 위), 닫으면 캔버스로 돌아온다 | `overlay.json`의 `projects.<경로>.torn.<노트>`: `{screenX, screenY, w, h, pinned}` |

- 모드 전환은 제목줄의 `▦ 그리드 / ✥ 캔버스` 토글. 기본은 캔버스.
- 위치는 레포의 `sticky.json`에 쓰지 않는다. 터미널 배치(열기·크기·순서)와 섞이지 않고 레포도 더러워지지 않는다. 다른 컴퓨터에서는 처음 보는 배치(그리드 자리)에서 시작한다.
- 노트 파일이 사라지면 그 위치 기록도 다음 로드 때 지운다. 이름이 바뀌면(`note.move`) 위치 기록을 새 이름으로 옮긴다.
- 크기(card/half/page)와 높이(rows)는 그리드 모드에서는 지금처럼 `sticky.json`에, 캔버스 모드에서는 노트의 `w, h`로 따로 둔다(캔버스에서 크기를 바꿔도 터미널은 바뀌지 않는다).
- 떼어낸 노트도 같은 bridge 연결과 같은 렌더러를 쓴다. 체크·답하기 등 상호작용이 그대로 된다.

## 3.7 노트 크기 · 크게 보기 · 페이지

[사용자 결정] overlay에서도 노트를 크게/작게 볼 수 있고, 여러 페이지는 넘겨 본다(R-34). 터미널에 있는 것과 같은 기능이고 같은 설정을 쓴다.

| 기능 | overlay에서 | 저장 |
|---|---|---|
| 너비 | 노트 오른쪽 가장자리를 끌면 가장 가까운 비율(`1/4` `1/3` `1/2` `2/3` `3/4` `1`)에 붙는다. `-` / `=` 키는 비율을 한 단계씩. 바꾸는 동안 테두리에 새 비율이 잠깐 보인다 | `sticky.json`의 노트 `size`, 비율로 쓴다 (터미널의 `+` `-`, `stickypane set size=1/3`과 같다). 옛 이름(`card` `half` `page`)은 읽기만 하고, 다음에 바뀔 때 비율로 다시 쓴다. 터미널 배치도 같이 바뀐다 |
| 높이 | 노트 아래 가장자리를 끌어 늘리기·줄이기. 더블클릭은 "내용만큼" (터미널과 같다. 키는 `shift+↑` `shift+↓` 한 줄, `0` 내용만큼) | 노트 `rows`(줄 수로 환산). 0이면 내용만큼 |
| 크게 보기 | 노트를 더블클릭하거나 `Enter` → 노트 하나가 창 전체를 채운다(터미널의 zoom). `Esc`나 바깥 클릭으로 돌아온다. 크게 본 상태에서도 체크·답하기가 된다 | 저장하지 않는다(창의 상태) |

## 3.9 언어

[사용자 결정] 앱은 한국어와 영어를 지원한다(R-33).

- 언어 선택은 본체의 `language` 키(`sticky.json`, `stickypane language`)를 **공유**한다. 값은 `auto` | `ko` | `en`, `auto`는 본체 `i18n.Detect()`와 같은 규칙(STICKYPANE_LANG → LC_ALL → LC_MESSAGES → LANG → 시스템). bridge가 `board.load`의 `settings.language`에 **해석된 값**(`ko`/`en`)과 선택값을 함께 준다.
- 홈 창은 프로젝트에 속하지 않으므로 `~/.stickypane/overlay.json`의 `language`(기본 `auto`)를 따른다.
- 앱 설정(홈의 ⚙, 프로젝트 창의 메뉴)에 **한국어 / English / 시스템** 전환이 있다. 프로젝트 창에서 바꾸면 `settings.set {language}`로 그 board의 `sticky.json`에 쓰고 터미널 board도 같이 바뀐다. 바꾸면 다시 시작하지 않고 바로 다시 그린다.
- 앱 문구는 `overlay/frontend/src/i18n/{ko,en}.json`, 영어가 기준이고 빠진 키는 영어로 보인다. 손글씨 글꼴 Gaegu는 한글·라틴을 모두 갖고 있어 언어가 바뀌어도 글꼴은 그대로다.
- 노트 내용은 번역하지 않는다. 열 이름·카드 텍스트는 파일 그대로다.
- 날짜 묶음("오늘", "어제", "10월 27일" / "Today", "Yesterday", "Oct 27")과 경과 시간("2분 전" / "2m ago")은 `Intl`로 그 언어에 맞춘다.

## 3.10 접근성

- 대비: 본문 글자는 `--ink` on `--paper`. 카드 글자는 wash 위 진한 색(`Text`를 wash 위와 wash·빗금 50% 혼합 위에서 4.5:1이 되도록 필요한 만큼만 검정 쪽으로 어둡게 한 값). 테마마다 4.5:1을 넘는지 테스트한다(밝은 테마의 노란 카드가 가장 위험).
- 색만으로 상태를 말하지 않는다: 정체는 색 + 동그라미 + 경과 시간 숫자, 체크는 색 + ✓ + 취소선.
- 키보드: 탭 이동(`Tab`), 노트 사이(`←→↑↓`), 체크(`Space`), 크게 보기(`Enter`), 편집기로 열기(`E`), 크기(`-` / `=`), 페이지(`[` / `]`), 생성(`A`, 터미널의 `a`와 같은 카탈로그), 돌아가기·숨기기(`Esc`). 터미널의 키와 겹치게 고른다.
- 손글씨가 읽기 어려운 사람을 위해 단정 스타일이 있다.
- `prefers-reduced-motion`은 [04 §4.6](04-motion.md#46-동작-줄이기).

## 3.11 시스템: 크기·규칙·컴포넌트·아이콘

[사용자 결정] 색과 손그림 부품(3.3–3.4.1)만으로는 "시스템이 없는" 화면이 됐다(이름이 두 줄로 꺾이고, 긴 경로가 제목줄을 차지하고, 모든 테두리가 기울고 떨리고, 버튼이 없었다). 그래서 크기 토큰, 손그림을 쓰는 곳의 규칙, 컴포넌트, 아이콘을 하나로 정한다. 기준은 Linear·Raycast·Things의 단정한 크롬 위에 Excalidraw 같은 노트다. 견본 페이지는 개발 빌드의 `?demo=system`(`?mode=light|dark`, `?style=neat`, `?lang=en`, `?density=compact`, `?theme=`).

### 3.11.6 창 버튼과 종료

[사용자 결정] 창에 닫기·최소화가 보여야 하고, 앱을 끝내는 길이 있어야 한다.

| | macOS | Linux |
|---|---|---|
| 창 버튼 | 숨긴 inset 제목줄(`MacTitleBarHiddenInset`)로 시스템 신호등이 우리 제목줄 왼쪽 위에 놓인다. 제목줄은 52px, 왼쪽 76px를 비운다 | 프레임 없는 창, 제목줄 오른쪽에 최소화·닫기 IconButton(같은 아이콘 가족) |
| 알리는 법 | 셸이 창 URL에 `?chrome=mac` | `?chrome=own` |

- 홈·프로젝트·떼어 낸 노트 창 모두 같은 제목줄을 쓴다(홈도 프레임 없는 창이 됐다).
- **닫기**는 그 창만 닫는다. 앱은 트레이에 남는다. 홈은 닫으면 숨는다.
- **종료**: 제목줄 ⋯ 메뉴와 트레이 메뉴 끝의 "stickypane 종료", macOS 앱 메뉴의 Quit(⌘Q).
- 처음 창을 닫을 때 한 번만 "트레이에 남아 있어요 · stickypane 종료" 토스트(알림 코드 `stayInTray`). 본 것은 `overlay.json`의 `trayHint`에 남는다. 남은 창이 없으면 홈이 나와서 말한다.
